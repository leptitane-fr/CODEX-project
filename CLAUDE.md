## What this repository actually is

This repo is named `TEI-reproductibility` and is meant to hold a **reproducibility
package for the "Theory of Informational Emergence" (TEI)** — a physics preprint by
Stéphane Goulet proposing that the observable universe emerges from a discrete,
timeless informational substrate via Γ-convergence from causal graphs to continuous
field theory.

**Important: the repository is currently almost empty.** As of this writing the only
substantive file is `README.md`. That README describes an *aspirational* layout:

```
sim/                # Core simulation scripts
  graph_generators.py
  poincare_check.py
  gamma_convergence.py
  hyperbolicity_test.py
tests/               # Pytest unit tests
data/                # Input/output datasets
figures/             # Generated figures
math/                # Notes & derivations
README.md
REPRODUCIBILITY.md
environment.yml      # Conda environment
CITATION.cff
LICENSE
```

**None of `sim/`, `tests/`, `data/`, `figures/`, `math/`, `environment.yml`,
`REPRODUCIBILITY.md`, `CITATION.cff`, or `LICENSE` exist in the repository yet.**
Do not assume any of this scaffolding is present — check with `ls`/`Glob` before
referencing a path from the README. If asked to implement pieces of the
reproducibility package, treat the README's structure as the target design to build
out, not as a description of existing code.

## Working in this repo

Because there is no existing code, build system, lint config, or test suite:

- There are currently no commands to run for build/lint/test — nothing to invoke
  until Python source and an `environment.yml`/`requirements.txt` are created.
- When implementing simulation scripts described in the README (e.g.
  `sim/graph_generators.py`, `sim/poincare_check.py`, `sim/gamma_convergence.py`,
  `sim/hyperbolicity_test.py`), follow the CLI conventions already implied by the
  README's usage examples: argparse-based scripts taking flags like `--dim`, `--N`,
  `--seed`, `--out`, `--graph`, `--samples`, `--Ns`, writing artifacts into `data/`
  (datasets, e.g. `.npz` graph seeds) or `figures/` (generated plots, e.g. `.png`).
- Unit tests belong in `tests/` and should be runnable via `pytest -q` (per the
  README's reproducibility steps) — keep this working if you add tests.
- The README references a `conda` environment named `tei` defined in
  `environment.yml`. If you add Python dependencies, add/update `environment.yml`
  rather than inventing a different dependency mechanism, to stay consistent with
  the documented reproduction steps.
- Mathematical notes/derivations belong under `math/` as described in the README.

## Conventions

- Commit messages and code comments in this repo have so far been minimal/generic;
  no strong established style to match yet. Use clear, descriptive commit messages.
- The project targets falsifiable, citable scientific results (see the Falsifiable
  Predictions table and Citation block in `README.md`). If you add simulation code,
  prefer reproducible, seeded randomness (the README already uses `--seed`) and
  deterministic output paths so results can be regenerated and compared.
- Keep `README.md`'s "Repository Structure" section honest: if you add or remove
  top-level directories, update that section (and this file) to match reality.
